# 后台测试

## 0.4.0-rc.1 独立 VPN

Android 15 x86_64 模拟器中，关闭 Clash，系统 HTTP 代理为空，澜流未加入电池优化白名单。BubbleUPnP 本机播放器用两首各 3 分钟的合成 WAV 验证实际 VPN 路径。系统记录的 VPN 路由仅包含测试源 IP 和接口地址，应用范围仅为 BubbleUPnP。

- 关闭 Wi-Fi 后启动 VPN，通过蜂窝取流。播放队列期间切到 Wi-Fi，退出两款应用界面并锁屏。播放器自然切到第二首并推进至 63 秒，累计由 VPN 中继交付约 61.6 MB，进程保持不变，没有中继错误。
- 第二首仍有上游读取的 60 秒样本中，澜流平均使用单核的 4.7%，样本末 PSS 约 52 MiB。所有取流结束后，锁屏空闲 60 秒的样本中，平均使用单核的 0.10%，PSS 约 59 MiB，音频缓存和客户端数归零，CPU 唤醒锁释放。
- 签名候选版覆盖安装 0.3.7 后保留配置的音源。关闭 Wi-Fi 冷启动，BubbleUPnP 实际播放时交付约 33.7 MiB。点击停止后，Android 移除定向路由和前台服务。
- 24 项 JVM 测试、6 项 Android 仪器测试、Debug 和 Release Lint 通过。模拟器强制 Doze 下，Debug 回环验证的 800,000 字节通过哈希校验，系统未报告网络受限。注入 SIGKILL 后，模拟器 90 秒内未自动重建 VPN 会话。此前台会话采用 Android 的 START_STICKY，恢复取决于系统是否重启服务。
- Debug 回环的 32 MiB 慢速读取测试跨 Wi-Fi、蜂窝数据和一次短时无网络，耗时 83.3 秒，完整字节的 SHA-256 一致。
- 这些测量以模拟器上相同的 CPU 计数器和进程报告为准。真实 TIDAL 在线曲目、设备温度和厂商的后台电池管理策略仍需要另行验证。

## 当前验证范围

2026-10-27，用户确认：**本项目在 BubbleUPnP 软件取流 TIDAL 音源的场景中已验证有效。**

0.3.7 的 JVM 测试覆盖 HTTP 字节转发、Range 条件、预检隔离与去重、缓存容量、重试、停止、配置校验和适配。Android 仪器测试覆盖后台心跳、通知时间、资源释放、监听恢复、Wi-Fi 重连、配置文件中断保存和诊断历史上限。

### 0.3.7 性能数据

测试环境为 Android 15 / API 35 模拟器。以下数据为单次实验或短时采样。

0.3.7 通过 29 项 JVM 测试、6 项 Android 仪器测试和 9 项后台取流场景。锁屏慢速读取 32 MiB 用时 83.1 秒，长度及 SHA-256 一致。另一次测试中锁屏空闲 180 秒，唤醒锁已释放，随后由原进程继续取流并通过字节校验。本次后台矩阵未复测强制 Doze 与系统受限联网。

| 检查 | 观察 |
| --- | --- |
| BubbleUPnP 播放 TIDAL | 验证了直连及经 Rill 取流，并复测暂停、跳转、切歌、锁屏和 Wi-Fi 重连。候选版的 30 秒样本中，Rill 在空闲时约占单核 0.10%、PSS 39 MiB，在 4 路与 8 路取流时约占单核 3.4%、PSS 46–48 MiB。 |
| 候选版高频取流 | 150 秒内对 428 个请求逐一校验，共传输 342.4 MB。预热后每次采样均为 118 个文件描述符，取流时 38 个线程、PSS 约 52–54 MiB。锁屏空闲 80 秒后线程降至 29 个，音频缓存清空，唤醒锁释放，原进程继续取流。 |
| 周期诊断快照 | 注入相同的 900 条采样和 200 条事件后，单次周期快照由 467,517 字节减至 16,093 字节。手动导出及正常停止仍保留完整的有界历史。 |

模拟器实验记录取流字节和播放器状态。特定厂商的后台策略、实体设备的长时功耗及音频输出需要实机验证。

### TIDAL 播放列表自然切歌

在 Android 15 模拟器上，BubbleUPnP 使用本机播放器和三首真实 TIDAL 曲目的队列。确认首曲取流后回到桌面并锁屏，之后不操作播放器。0.3.7 完成了两次自然切歌。切到第三首时约 17 秒处于缓冲，Rill 的 Wi-Fi 状态可用，收到请求并重新取得唤醒锁后约 10 秒才通过上游预检。期间记录了一次重试。

用同一 HTTP 测试源在锁屏下对照，令下一首的第一次预检保持无响应，第二次返回正常。0.3.7 的首包为 10.41 秒，0.3.8-rc.1 为 3.83 秒，两版都重试一次并通过 800,000 字节的长度与 SHA-256 校验。候选版的日志标明首次预检在 3.5 秒超时。

候选版用原队列的第二首与第三首复测。锁屏进入轻度待机后，第二首播完，约 7 秒内自动起播第三首。确认第三首继续播放，Rill 额外交付约 11.4 MB，未发生重试或错误。签名候选包从 0.3.7 覆盖升级后保留设置，亮屏后台和锁屏取流校验均通过。

#### 首批音频交付

再次测量同一对曲目时，从锁屏曲末的播放器停止事件到 rc.1 收到下一首请求约 0.81 秒。Rill 约 1.03 秒后交付首批音频，其中约 0.25 秒是上游预检，约 0.78 秒是预检结束后等待 512 KiB 连续数据。播放器的后续缓冲也计入开始播放之前的间隔。

rc.2 收到并校验了请求范围内的首批字节即可发送。用同一 HTTP 源将预检之后的分块延迟 4 秒，rc.1 首字节为 4.17 秒，rc.2 为 31 毫秒。两版交付的 800,000 字节长度和 SHA-256 一致。该测量记录首字节到达，整段仍需等上游返回。

真实 TIDAL 复测使用同一对曲目。rc.2 在曲末约 0.76 秒后收到请求，191 毫秒后交付首批音频，其中预检耗时 176 毫秒。播放器约 3.88 秒后进入新曲的播放状态，总间隔约 4.83 秒。首批音频之后的时间包含后续取流和播放器缓冲。单次样本的完整切歌耗时会随网络和播放器状态变化。

### 0.3.8-rc.3 故障回归

33 项 JVM 测试、6 项 Android 仪器测试和 13 个后台场景通过。旧版遇到预检 503 后直接返回 502。候选版在预检和分块各遇到一次 503 的情况下，分别交付了 800,000 字节，两次长度和 SHA-256 均一致。并发回归覆盖同一预检失败后的四个等待者，以及失败后新请求的恢复。

锁屏慢速读取 32 MiB 用时约 83 秒，内容校验一致。锁屏空闲 180 秒后由原进程继续取流，恢复前唤醒锁已释放。强制 Doze 时未观察到模拟器阻断联网，退出后取流正常。本轮未注入系统受限联网模式。

上游预检被故意挂起时，点击停止后约 0.11 秒内本地请求断开，唤醒锁释放。重新开启后交付了通过校验的 800,000 字节。签名包从 rc.2 覆盖安装后保留设置，亮屏后台、锁屏取流及停止服务均通过。

真实 TIDAL 锁屏播放的 66 秒样本中，Rill 平均使用单核的 0.11%，末次采样 PSS 约 50 MiB。样本结束时播放器仍在推进，Rill 已释放唤醒锁，音频缓存为零。

真实 TIDAL 队列的前两首完整播放至曲末，均自然切换到下一首。第三首继续推进至 10 秒，本轮确认三首均通过中继，累计交付约 56 MB，记录的重试和错误均为零。

### 0.3.8-rc.4 蜂窝网络

在 Android 15 模拟器关闭 Wi-Fi 后，系统显示蜂窝已连接，rc.3 的本地健康检查通过，但音频请求等不到首字节。rc.4 通过 7 项 Android 仪器测试和 6 项后台场景。锁屏下从 Wi-Fi 切到蜂窝再切回，三次均交付 800,000 字节并校验 SHA-256，服务进程保持不变。

签名包从 rc.3 覆盖安装后保留设置。关闭 Wi-Fi 后启动服务，使用蜂窝完成亮屏后台和锁屏下各 3 次取流，全部通过字节校验。

BubbleUPnP 的 TIDAL 默认蜂窝音质为 AAC 320 kbps，在本次测试配置中这一路径没有匹配中继规则。将测试设备的 `Mobile audio quality` 临时设为 `FLAC 44.1 kHz / 16-bit` 后，关闭 Wi-Fi 并锁屏，确认 Rill 经蜂窝交付约 3.6 MB 真实 FLAC 音频，播放进度持续推进，记录的错误为零。

## 复现方法

需要 Python 3.9+、ADB、独立 Android 13+ 模拟器，默认接入点为 `AndroidWifi`。安装 Debug APK 并运行仪器测试：

```powershell
.\gradlew.bat :app:assembleDebug :app:connectedDebugAndroidTest
adb -s emulator-5580 install -r app/build/outputs/apk/debug/app-debug.apk
python tools/background_matrix.py --adb <adb路径> --serial emulator-5580 --output .local/background-matrix/run --duration 120
```

脚本拒绝真实设备。它会覆盖测试应用设置、切换 Wi-Fi 和电量模式、注入网络限制，以及终止或暂停应用进程；请使用独立模拟器。异常退出会尝试恢复系统状态，ADB 故障后应手动核对。结果输出为 `device.json`、`results.json`，不应提交本机诊断与私人配置。脚本走 Debug 回环中继入口，用来检查字节完整性和后台恢复。TUN 路径另用 BubbleUPnP 实际播放验证。

测试以普通界面开启服务后切到系统设置，不依赖 instrumentation 持续保活。上游为本机 HTTP/1.1 服务，使用合成二进制数据，逐请求校验长度及 SHA-256；长流为 32 MiB，超过单任务缓存上限。

| 场景名（可传给 `--only`） | 检查 |
| --- | --- |
| `slow_preflight_isolation` | 慢预检不阻塞另一首歌 |
| `upstream_transient_recovery` | 预检和分块各注入一次 503，验证自动重试和完整字节 |
| `screen_on_background` | 切出界面后持续切歌 |
| `screen_off_long_stream` | 锁屏、慢速读取完整 32 MiB |
| `battery_saver` | 节电模式下持续切歌 |
| `doze_without_exemption` / `doze_with_exemption` | 记录实际 Doze 与网络状态 |
| `doze_exit_recovery` | 退出 Doze 后恢复 |
| `wifi_reconnection` | Wi-Fi 断开后自动恢复 |
| `cellular_handover` | 锁屏从 Wi-Fi 切到蜂窝再切回，逐段校验字节并确认进程未重启 |
| `restricted_network_recovery` | 收到受限回调、解除限制后恢复 |
| `process_suspension_recovery` | 暂停进程 7 秒后继续请求 |
| `process_death_recovery` | START_STICKY 重启与新请求 |
| `post_recovery_background` | 恢复后继续后台切歌 |
| `buffered_playback_idle_resume` | 锁屏空闲 180 秒后确认已释放 CPU 锁，再重新取流 |

判断报告是否更新时，同时检查 `snapshot_age_ms` 和 `service_tick_age_ms`。快照内的心跳年龄小，不代表快照本身仍然新鲜。

## 历史基线：2026-10-12

环境为独立 Android 15 / API 35 x86_64 模拟器（2 核、2 GiB）。0.3.5 的慢预检曾让另一歌曲超过 5 秒无法返回；0.3.6-rc1 将预检按 URL 隔离，同 URL 合并等待，创建任务计入容量限制。

| 候选版场景 | 记录 |
| --- | --- |
| 慢预检隔离 | 正常歌曲首包 0.203 秒，最终包复测 1.375 秒 |
| 亮屏后台 / 节电模式，各 120 秒 | 各 57 个请求，长度与哈希均一致 |
| 锁屏读取 32 MiB | 83.67 秒，内容一致 |
| Wi-Fi 断开 8 秒后恢复 | 等待请求 14.64 秒完成，无需打开界面 |
| 暂停进程 7 秒 | 独立复测总耗时 8.188 秒，最大心跳间隔 8,064 ms |
| 杀进程后恢复 | 约 2.53 秒出现新进程及健康监听，随后取流成功 |
| 锁屏空闲 180 秒 | 原进程仍在；新请求 800,000 字节，首包 0.594 秒 |
| 正式签名候选覆盖 0.3.5 | 升级成功，亮屏与锁屏各 13 次取流均校验通过 |

非白名单 Doze 已确认进入 IDLE，但该链路仍可联网，只记为观察。受限联网补测收到 `wifi.blocked=true`，随后 ADB 超时使自动恢复和紧接的暂停测试失败；保留这些失败记录。独立解除限制后，未打开 Rill，32 秒内 12 个新 URL 请求通过。单独重跑暂停测试通过。

这些记录没有重现用户手机上「必须切回界面」的完整现象，也不能证明预检锁是该现象的唯一原因。历史记录是基线，不代替当前发布的重新验证。

## 真机问题定位

导出诊断时，同时记录问题时间、手机型号与完整系统版本。结合 `pending_preflights`、`open_clients`、`network.transport`、`network.blocked`、`service_max_tick_gap_ms`、进程 ID 与事件，可区分请求等待、系统网络限制、进程暂停和重启。旧版本的网络状态位于 `wifi` 字段。

`battery_exempt` 表示 Android 电池优化豁免状态，不代表厂商界面的后台策略。日志保留有限历史，应在恢复后尽快导出。

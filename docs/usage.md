# 使用指南

## 安装

从 [GitHub Releases](https://github.com/ChrisDong-THU/Rill/releases/latest) 下载 `Rill-<版本>.apk`，支持 Android 8.0 及以上。可用附件 `SHA256SUMS.txt` 校验下载内容。

## 已验证场景

本项目在 **BubbleUPnP 软件取流 TIDAL 音源**的场景中已验证有效。按照下述步骤配置 Clash 与澜流后，在 BubbleUPnP 中播放 TIDAL 音源即可使用中继。

## 配置播放

1. 手机连接 Wi-Fi。在 Clash 分应用设置中，将「澜流」设为绕过代理；播放器仍由 Clash 接管。
2. 打开澜流「配置」，选择完整的 Clash YAML 文件，或输入返回完整 YAML 的订阅地址。
3. 适配后点击「导入 Clash」，在 Clash 保存并选用该配置。客户端不支持导入接口时，使用「保存文件」手动导入。
4. Clash 使用规则模式，将「澜流 · 音频」组选为 `Rill Local`。遇到名称冲突时，本地节点会带数字后缀。
5. 回到澜流点击「开启」，按提示设置通知与后台运行权限，再开始播放。
6. 停止澜流前，将音频组切回 `DIRECT`。

## 设置

| 项目 | 行为 |
| --- | --- |
| 连接上限 | 默认 8，范围 1–16；调低后，已有连接先完成 |
| 加速链接 | HTTP 地址或域名，每行一个，最多 16 个；可指定端口 |
| 配置大小 | 输入和适配结果均不超过 4 MiB |
| 配置更新 | 修改目标后重新适配原配置；需再次导入 Clash |

目标设置只保留域名和端口，不保存路径与签名参数。原节点、代理组与规则保留，新增规则优先生效；YAML 注释不保留。失败的导入会保留上次适配结果，页面显示失败原因。

导入 Clash 的是配置快照。订阅更新后，需要重新读取、适配和导入。

## 后台与限制

- 上游须支持标准 HTTP Range。HTTPS 音频、需要额外 Cookie / Authorization 的来源，以及不支持分段的服务器暂不支持。
- 中继只监听本机 `127.0.0.1:18889`；音频取流绑定 Wi-Fi，不自动切换移动数据。
- 切出界面后，前台服务继续维护会话。Wi-Fi 恢复后，新请求使用恢复的网络；播放器已终止的请求可能需要重新播放。
- 监听故障按 2–30 秒退避重试，恢复期间仍可停止服务。
- 通知显示连接数与下载速度；同一次会话复用启动时间，具体展示由系统决定。

厂商后台控制、系统省电策略与播放器行为可能影响播放。模拟器测试范围见 [后台测试](background-testing.md)。

## 排障

| 现象 | 检查 |
| --- | --- |
| 开启后没有流量 | Clash 是否启用适配配置、音频组是否选择本地节点、目标是否匹配 |
| 只在后台或锁屏时中断 | 系统后台权限、电池优化、Wi-Fi 状态，以及诊断中的心跳与网络受限信息 |
| 导入失败 | 是否为完整 Clash YAML、文件大小、重复字段和订阅响应 |

在「记录 → 导出诊断」保存报告，并记录问题时间、手机型号、完整系统版本、播放器及网络环境。诊断不导出原始音频 URL；分享前仍应检查域名、设备信息和文件中的个人内容。请勿提交订阅链接、节点密码或完整配置。
